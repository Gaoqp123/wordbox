# ADR-0006：复习调度用 FSRS

- 状态：已接受
- 日期：2026-10-04
- 规划条目：§2 D6
- 关联：ADR-0004（历史与生词本分离）

## 背景

卡片复习需要一个调度算法：给定这张卡的复习历史和本次评分，算出下次该在什么时候出现。

## 决策

用 `ts-fsrs`。所有计算封装在 `shared/domain/srs`，对外只暴露一个纯函数
`schedule(card, rating, now)`，界面不直接依赖这个库。

## 备选方案

- **SM-2**：经典、简单，但同等记忆效果下复习次数更多，长期看复习量偏大。
- **自研算法**：可控性最高，但等于把"记忆模型"当成练手项目，
  收益远不抵调参和验证的成本。

## 后果

- 好：成熟实现，开箱即用；同等保留率下复习量更少，契合"不定量、不打卡"的定位。
- 好：包在纯函数后面，将来换算法只改一个文件，界面与数据层不受影响。
- 代价：需要理解 FSRS 的参数含义，其中 `requestRetention`（默认 0.9）要暴露给设置项。
- 代价：Card 表结构需要容纳 stability / difficulty / elapsedDays 等 FSRS 专有字段。

## 复核触发条件

- 若 FSRS 的实际调度与你的记忆感受长期不符（例如到期堆积无法消化），
  先调 `requestRetention`，再考虑换算法；
- 若 `ts-fsrs` 停止维护，纯函数封装使替换成本保持在单文件级别。
