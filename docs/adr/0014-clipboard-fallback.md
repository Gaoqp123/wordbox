# ADR-0014：模拟复制降级为加速路径，剪贴板兜底成为一等公民

- 状态：已接受（M0 实测后修订）
- 日期：2026-10-04
- 规划条目：§2 D14
- 关联：ADR-0003（显式快捷键）、ADR-0012（取词程序无关）

## 背景

ADR-0012 把取词做成程序无关的，实现上只能靠"模拟一次 Ctrl+C"。
规划里把它写成主路径，并把"用户自己 Ctrl+C"列为兜底。M0 的技术验证推翻了这个主次关系。

实测（2026-10-04，装有卡巴斯基的 Windows 机器）：

1. 首次取词成功；
2. 之后无论换哪个程序、哪种触发方式都失败；
3. 诊断面板显示模拟按键时的前台窗口正常、剪贴板毫无变化；
4. 最终确认是安全软件拦截，并且拦截逐步升级——从"阻止合成按键"到
   **"拒绝创建子进程"（`spawn EPERM`）**。

原因不难理解：一个看不见的进程往别的窗口伪造键盘输入，正是键盘记录器与远控木马的行为特征。
行为检测"先观察、后判定"，所以表现为第一次放行、之后全拦。

## 决策

把模拟复制从"主路径"降级为"加速路径"，剪贴板兜底成为一等公民：

1. 快捷键触发时先试模拟复制；
2. 失败即改读用户自己按 Ctrl+C 后的剪贴板内容，并**在界面上标明来源**；
3. 模拟复制连续失败 3 次、或遇到无法创建子进程这类硬错误时，**立即熔断**，
   本会话内不再尝试，避免每次按键都触发一次安全软件拦截提示；
4. 与上次兜底内容相同的剪贴板文本按旧内容处理，不冒充本次查询；
5. 兜底不可用时给出明确指引（"选中 → Ctrl+C → 快捷键"），而不是含糊的"没取到东西"。

## 备选方案

- **坚持模拟复制，让用户给安全软件加白名单**：可行但脆弱——不能白名单 `powershell.exe`
  这类被滥用最多的程序；换机器、换杀软、升级版本都会重新踩一遍。
- **换原生模块在自己进程里调 SendInput**：绕开"隐藏 PowerShell"这一层，
  但仍属于伪造输入行为，且要引入原生模块重编译，未见得能躲过行为检测。
- **用 UI Automation 读取选区文本**：不模拟任何按键，安全软件不会拦，
  是恢复"一键取词"的正路；代价是不同程序对 UIA 的支持参差，需要单独验证一轮。

## 后果

- 好：工具在各种安全软件环境下都可用，不再与杀软对抗。
- 好：行为完全可解释——界面上永远标明这次内容是我们复制到的，还是你复制、我们读到的。
- 代价：多按一次 Ctrl+C。
- 代价：多了一套熔断状态与"旧内容"判定，需要单元测试覆盖。
- 遗留：一键体验在装有行为检测安全软件的机器上不可靠；将来优先考虑 UI Automation，
  而不是继续强化按键模拟。该评估排在 M1/M2 之后。

## 复核触发条件

- 若 M1/M2 之后仍希望恢复一键取词，则为 UI Automation 方案做一次专项技术验证；
- 若实测发现多数目标程序都支持 UIA 读选区，可把 UIA 提为主路径、模拟复制作为备份。
