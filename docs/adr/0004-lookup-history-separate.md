# ADR-0004：查询历史与生词本分离

- 状态：已接受
- 日期：2026-10-04
- 规划条目：§2 D4
- 关联：ADR-0005（显式收录）

## 背景

"查过的词"和"要背的词"看起来是同一批数据，直觉上会想合并成一张表。

## 决策

分成两处存储：`lookups`（每次查询都自动记录）与 `words`（只有显式收录才写入）。
两者的唯一纽带是 `Lookup.promotedWordId`。

## 备选方案

- **查过即收录**：实现最省事，但查询是高频动作、背词是低频且昂贵的承诺，
  两者混在一起会让生词本迅速失去意义。

## 后果

- 好：查询历史可以放心地全量记录，反而成为有价值的信号——
  "这个词我查了三次"正是从这张表算出来的。
- 好：`promotedWordId` 顺带成为 F-15（历史批量提升）的基础。
- 代价：多一张表、多一次写入，以及"历史 → 生词本"的转换逻辑。

## 复核触发条件

若将来引入"按语境复习"（同一词的不同用法分开练），`contexts` 需要从 JSON 数组升级为独立表——
但那是数据结构演进，不是本决策的推翻。
