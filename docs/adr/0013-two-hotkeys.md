# ADR-0013：两个快捷键——查词 / 查句

- 状态：已接受
- 日期：2026-10-04
- 规划条目：§2 D13
- 关联：ADR-0012（取词程序无关）、ADR-0011（语境留存）

## 背景

取词时需要区分两种意图：只查一个词，或者"整句读不懂，想逐个词看"。
一个按键既可以自动判断内容，也可以由用户明确指定。

## 决策

两个快捷键，各管一件事：查词（默认 `Ctrl+Alt+D`）把选中的东西整体当一个词条；
查句（默认 `Ctrl+Alt+S`）弹窗显示原文、切成可点的词，点哪个查哪个。

## 备选方案

- **一个快捷键按内容自适应**：v0.2 的原始做法。少一个要记的组合，
  但要处理一堆边界情况（`ubiquitous.` 算词还是算句？短语算不算句子？），
  而且猜错的代价是打断阅读。

## 后果

- 好：意图由用户表达，不做猜测；边界情况大幅减少；两个键也更容易记住各自用途。
- 代价：要记两个组合；全局快捷键是**抢占式**的，注册成功就等于系统里这个组合被吃掉了。
  因此默认值必须冷门、设置里必须可改，且 `globalShortcut.register` 返回 `false` 时
  必须显式提示，不能静默失效。

## 复核触发条件

若两个键在实际使用中频繁按错，或某个默认组合与常用软件冲突，则调整默认值——
但"两个意图分开"这个结构本身不因此改变。
