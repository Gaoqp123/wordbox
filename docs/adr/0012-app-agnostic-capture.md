# ADR-0012：取词程序无关

- 状态：已接受
- 日期：2026-10-04
- 规划条目：§2 D12
- 关联：ADR-0002（不做阅读器）、ADR-0013（两个快捷键）、ADR-0014（剪贴板兜底）

## 背景

取词范围决定了这个工具的适用面。最省事的做法是只针对主用阅读器（Readest）做适配。

## 决策

整条取词链路只依赖一个前提：**目标程序支持把选中文本复制下来**。
不为任何单一软件定制，也不做浏览器扩展。

## 备选方案

- **针对 Readest 定制**：实现简单、效果可控，但只覆盖一种场景；
  换一个阅读器、换到浏览器或 PDF 就全部失效。

## 后果

- 好：阅读器、浏览器、PDF 阅读器、Office、聊天软件一次性全覆盖。
- 好：需求从"适配 N 个软件"变成"处理一类通用问题"，维护成本不随软件数量增长。
- 代价：拿不到选区就只能靠系统手段（合成按键），而这会受到操作系统与安全软件的约束。
- 代价：必须自行处理"没选中""选中不完整""剪贴板被污染"这些边界情况，
  判定逻辑必须是可单测的纯函数（`shared/domain/grab-guard.ts`）。

## 复核触发条件

- 若合成按键在所有平台的可行方案里都被安全软件阻断，且用户不接受"多按一次 Ctrl+C"
  的兜底路径，则需要重新评估：改用 UI Automation 读取选区，或退回到针对特定软件的适配。
